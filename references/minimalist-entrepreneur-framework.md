# Minimalist Entrepreneur Coaching Framework

> **Source:** Sahil Lavingia's "The Minimalist Entrepreneur" — 10 Claude Code skills adapted for ongoing coaching use.
> **Purpose:** Default framework to apply whenever the user mentions any project, idea, or business decision.

---

## How to Use This Framework

Whenever the user mentions a new project, idea, or business topic:

1. **Listen for signals** — Which stage are they in? (just an idea, building, selling, scaling)
2. **Apply the relevant skill(s)** — Don't dump all 10 at once; use what's relevant
3. **Ask, don't tell** — The framework is a set of questions, not prescriptions
4. **Push toward action** — Every conversation should end with "what will you do this week?"

## Skill 1: Find Community

### Core Principle
Start with community, not with a product idea. The best minimalist businesses are built by people already deeply embedded in a community who notice a problem worth solving.

### Coaching Questions
1. What communities are you already a part of? (professional groups, hobbies, forums, alumni networks, parent groups, etc.)
2. Where do you spend your time online? (Reddit, Discord, Slack groups, Twitter/X, forums, etc.)
3. What problems do you hear people complain about repeatedly?
4. Which of these communities would you be excited to serve for years?

### Evaluation Criteria
- Are you a genuine member? (contributing, not lurking)
- Is the problem painful enough that people would pay?
- Can you reach these people directly?
- Is the community large enough but not too large? (niche you can dominate)

### Anti-patterns
- ❌ Inventing a community from scratch
- ❌ Choosing a community purely for market size
- ❌ Skipping participation, jumping straight to "what can I sell"
- ❌ Targeting too broad ("everyone who uses the internet")

### Output
Help narrow to 1-3 communities with specific problems identified:
- The community
- The persistent problem
- How the user is connected
- Where the community gathers

## Skill 2: Validate Idea

### Core Principle
Validation happens through selling, not building. Most founders spend months building a product nobody wants.

### The 4-Step Validation Process

#### Step 1: Define the Problem (not the solution)
- Who specifically has this problem? (Not "businesses" but "freelance graphic designers who struggle with invoicing")
- How are they solving it today? (Current workaround = your real competition)
- How painful is this? (Mild annoyance vs. hair-on-fire)
- Would they pay to make it go away?

#### Step 2: Can You Solve It Manually First?
- Do it yourself first. Hire yourself.
- Write down every step on paper.
- If you can solve it manually for a few people, you can eventually automate it.
- Example: Gumroad started with Sahil manually collecting PayPal info and paying creators one by one.

#### Step 3: Will People Pay?
- Can you charge for this manual service right now?
- Have you talked to at least 10 potential customers?
- Have at least 3 said they'd pay (or actually paid)?
- What price point feels natural?

#### Step 4: Four Questions Before Building
1. Can I ship it in a weekend?
2. Is it making my customers' life a little better?
3. Is a customer willing to pay me for it?
4. Can I get feedback quickly?

### Red Flags (Do NOT Build)
- Nobody is currently trying to solve this problem
- You can't name 10 specific people who have this problem
- Only validation is "my friends think it's cool"
- You need to educate people they have this problem
- Building for a community you don't belong to

### Green Flags (Worth Pursuing)
- People already paying for inferior solutions
- You've manually solved this for a few people and they loved it
- Community actively complaining about this problem
- Can describe customer + pain point in one sentence
- You're scratching your own itch

### Output
Give a clear verdict:
- **Validated** → Proceed to MVP
- **Needs more validation** → Specific next steps
- **Pivot** → Fundamental changes needed

## Skill 3: MVP (Minimum Viable Product)

### Core Principle
Build as little as possible. The goal is to start delivering value to your community as quickly as possible.

### The Three Stages

```
Stage 1: MANUAL        Stage 2: PROCESSIZED      Stage 3: PRODUCTIZED
┌──────────────┐      ┌──────────────┐         ┌──────────────┐
│ You do it    │  →   │ Document it   │   →    │ Automate it  │
│ by hand for  │      │ on paper so   │        │ so customers │
│ each customer│      │ anyone can    │        │ use it       │
│              │      │ do it         │        │ without you  │
└──────────────┘      └──────────────┘         └──────────────┘
```

**Manual Stage:**
- You are the product. You are customer service, fulfillment, and engineering.
- Write down every step — this becomes your process.
- Example: Before Gumroad automated payouts, Sahil collected PayPal emails and sent payments manually.

**Processized Stage:**
- Document your process on a piece of paper so anyone could do it.
- If you go on vacation, someone else can take over.
- This is your "magic piece of paper."

**Productized Stage:**
- Now automate each task so customers can use your product without you.
- Only build what you've already proven works manually.

### The Four Build Questions
1. Can I ship it in a weekend? If not, reduce scope.
2. Is it making my customers' life a little better?
3. Is a customer willing to pay for it? (Profitable from day one)
4. Can I get feedback quickly?

### What to Build
- Most apps are just **forms and lists** (CRUD: Create, Read, Update, Delete)
- Your MVP should be no more complex than that
- One thing. Your product does one thing, at first.
- No polish. CraigsList has never been pretty.
- Charge money. There's a huge difference between free and $1.
- Use existing tools: Carrd, Gumroad, Stripe, Airtable, Google Forms, Zapier, Notion

### What NOT to Build
- ❌ Features you'll need "someday"
- ❌ For scale (you don't have scale problems yet)
- ❌ Mobile app when a website works
- ❌ Code when a spreadsheet works
- ❌ Engineer when no-code tools work

### Essentials Checklist
- [ ] Name your business (two real words combined > made-up word; pass the "radio test")
- [ ] Buy a domain (~$10/year)
- [ ] Build a simple website (Carrd, Gumroad, or similar)
- [ ] Create social media accounts (personal + business)
- [ ] Set up payments (Stripe or Square — 2.9% + 30¢ per transaction)
- [ ] Create an email for customer communication

### Output
Help define:
1. The single thing their MVP does
2. The simplest possible implementation
3. What they can ship this weekend
4. Initial price point
5. How they'll collect feedback

## Skill 4: Processize

### Core Principle
Processize before you productize. Every great product started as someone doing the work by hand.

### The 6 Steps

#### Step 1: What's the Product Idea?
- What is the **one thing** this product does for a customer?
- What do they have before vs. after?
- If you had to deliver this with zero technology (just you, phone, spreadsheet), how?

#### Step 2: Who Needs This Today?
- Who is already trying to solve this with a workaround?
- Where do they hang out?
- Can you name 10 specific people with this problem right now?

#### Step 3: Design the Manual Version
- What does the customer give you?
- What do you do with it? (Every step, in order)
- What do you give back?
- How long does it take per customer?

#### Step 4: Write the Magic Piece of Paper
Document so clearly that someone else could do it:
1. **Trigger** — What kicks off the process?
2. **Steps** — Numbered list of exactly what to do
3. **Tools needed** — Spreadsheet, email, phone, etc.
4. **Time per customer** — How long each step takes
5. **Handoff** — How you deliver the result back

#### Step 5: Charge for It
- Set a price based on time + value to customer
- Reach out to 3 people from your community this week
- Deliver the manual version and collect payment
- Every interaction teaches you something building wouldn't

#### Step 6: When to Productize
Only automate what you've proven works manually:
- Delivered manual version to 10+ paying customers
- Can predict exactly what they'll ask for
- Steps on magic piece of paper haven't changed in weeks
- Spending more time on delivery than finding customers

**Then automate ONE step at a time.** Start with whatever takes the most time per customer.

### Output
Help create:
1. One-sentence description of what product does manually
2. The magic piece of paper — full manual process
3. List of 3 specific people to deliver to this week
4. Initial price point
5. First step to automate when ready (not now)

## Skill 5: First Customers

### Core Principle
Skip the launch. Focus on selling. "Viral success" is a myth.

### The Concentric Circles of Sales

```
        ┌──────────────┐
        │   FRIENDS    │
        │   & FAMILY   │
        └──────┬───────┘
               │
        ┌──────┴───────┐
        │   COMMUNITY  │
        │   MEMBERS    │
        └──────┬───────┘
               │
        ┌──────┴───────┐
        │   STRANGERS  │
        │  (COLD OUT.) │
        └──────────────┘
```

**Circle 1: Friends and Family**
- Pitch them on being customers, not investors
- If they won't buy, who will?
- Ask for honest feedback, not social media posts
- Kickstarter: "Support always begins with people you know"

**Circle 2: Your Community**
1. Make a list of everyone who has written/shared about a similar business
2. Contact them all personally — walk them through your product
3. Ask for candid feedback, not reviews

**Circle 3: Strangers (Cold Outreach)**
- Sahil literally scoured the web and emailed thousands of people personally
- Example cold email:
  > "Hi John, I saw you're selling a PDF on your website using PayPal, and manually emailing everyone who buys. I built a service called Gumroad which automates all of this. I'd love to show it to you: gumroad.com. Best, Sahil"
- Don't copy/paste. Each email refines your ability to write better.
- Use each rejection as a learning opportunity.

### Sales Mindset
- You're not convincing anyone. You're helping people.
- Turn every failed conversion into an insight
- Sales is an education process

### Pricing for Early Sales
- There is a massive difference between free and $1 ("zero price effect")
- Cost-based: Your costs + margin (20-50%)
- Value-based: What it's worth to customer, regardless of your costs
- Start low, raise over time
- Goal: eventually tiered pricing (economy, business, first class)

### Key Metrics
- **Manual sales = 99% of early growth.** Word of mouth = 99% of later growth.
- Slack's IPO: 575 customers = 40% of revenue
- $10/month × 200 customers = $2,000/month = less than 1 year at one per business day
- **Product-market fit** = repeat customers who sign up and use on their own

### When to "Launch"
Don't launch until you have 100 paying customers. Then launch as a **celebration** of your community's support, not as customer acquisition. Throw a party. Thank your customers.

### Output
Help create:
1. List of 10 friends/family to pitch this week
2. List of 10 community members to reach out to
3. Cold outreach template (personalized, not copy-paste)
4. Initial pricing strategy
5. Weekly sales goal and tracking method

## Skill 6: Pricing

### Core Principle
Charge something. Always. The zero price effect: people will line up for free brownies but the line disappears when you charge even 1 cent.

### Two Pricing Models

**Cost-Based Pricing**
- Calculate costs (hosting, time, materials, payment processing)
- Add margin (20-50% typical)
- Example: Retail stores double wholesale (50% margin)
- Best for: physical products, services with clear costs
- Used by: iTunes, iStockPhoto

**Value-Based Pricing**
- Price based on value to customer, not your costs
- Feature might cost you nothing but be worth a lot to customer
- Example: Netflix's multi-screen feature costs nothing but they charge premium
- Best for: software, digital products, high perceived value

### Pricing Principles
1. **Start low, raise over time.** Expected and healthy.
2. **Pricing is not permanent.** Another thing to iterate.
3. **Tiered pricing is the goal.** Like plane tickets: economy, business, first class.
4. **The zero price effect.** Never default to free. Even $1 changes everything.
5. **Free trials are table stakes.** Customers expect them. Always with clear path to paid.
6. **Don't confuse marketing with giving away your product.** Ad-driven models make charging later hard.

### How to Set Initial Price
1. What are your variable costs per unit/customer?
2. What are competing/alternative solutions charging?
3. What would make this a "no-brainer" for your ideal customer?
4. What price lets you be profitable from customer #1?

### Financial Independence Math
- How much do you need per month to sustain yourself?
- At your price point, how many customers is that?
- At one new customer per business day (260/year), when do you hit that?
- Example: $10/month, need $2,000/month = 200 customers = less than 1 year

### Output
Help determine:
1. Pricing model (cost-based, value-based, hybrid)
2. Initial price point with rationale
3. Potential tier structure for future
4. Number of customers needed for financial independence
5. When to revisit and raise prices

## Skill 7: Marketing Plan

### Core Principle
Marketing is sales at scale. But don't confuse marketing with advertising. Marketing is about making fans, not headlines.

### Prerequisites
Before marketing, you should have:
- A community you belong to
- A product people are paying for
- ~100 customers (repeat customers = product-market fit)
- Experience selling one-on-one (sales informs marketing)

### The Marketing Funnel
```
Engage → Follow → Research → Consider → Buy
```
Can't skip steps. Every customer goes through all five.

### Community vs. Audience
- **Community**: People who share interests (you're a member)
- **Audience**: Everyone you can reach when you have something to say
- Your community is part of your audience, but your audience is much larger

### Three Levels of Content

**Level 1: Educate**
- Share what you've learned from building your business
- 100 customers = 100 things worth sharing
- Doesn't need to be polished — just consistent

**Level 2: Inspire**
- Share your journey, struggles, successes
- Be vulnerable and authentic — like Gimlet's StartUp podcast
- Document your progress, not just expertise

**Level 3: Entertain**
- Hardest but most far-reaching
- Entertainment is king on every platform
- Example: "Entrepreneurship: work 60 hours a week so you don't have to work 40"

### Social Media Guide
- **Create two accounts**: Personal (you, the human) + business (the business)
- **Don't share what you ate for lunch.** Status updates won't grow audience.
- **Be authentic.** Focus on ideas, not self-promotion. Give, don't ask.
- **Build in public.** Share what you're working on, what you've improved, what you've learned.
- **Trust the feedback loop.** Post consistently, see what resonates, do more of that.
- **Pick one platform** that works for your business.

### Email: Own Your Audience
- Social media = rented land (algorithms change, accounts shut down)
- Email = owned land (direct line, no algorithm)
- Start building email list immediately
- Offer something valuable for an email (guide, PDF, checklist)
- Each email subscriber worth far more than a social follower

### Content Calendar
- Pick 1-2 platforms + email
- Post consistently (e.g., Twitter M/W/F, YouTube weekly)
- Quality over quantity — monthly newsletter with substance beats daily noise

### Spend Money Last
- Most growth you see is paid for. Don't be fooled.
- Only spend on ads after organic traction + known customer profile
- When you do spend, use lookalike audiences
- Spend on customers (rewards, loyalty) before acquisition
- Don't pay more than you make per customer

### Output
Help create:
1. Primary content platform and posting schedule
2. 5 content ideas for each level (educate, inspire, entertain)
3. Email list strategy (what to offer, how to collect)
4. "Build in public" plan — what to share from journey
5. When (if ever) to consider paid advertising

## Skill 8: Grow Sustainably

### Core Principle
Profitability is a superpower. It gives you infinite runway, clarity, and control.

### The Equation
**Profit = Revenue - Costs**
- Make more than you spend = company can go forever
- Make less = you will eventually fail

### Two Types of Costs

**Variable Costs (COGS)**
- Scale with each unit sold: payment processing, hosting, fraud prevention
- Example: At Gumroad, ~40¢ variable cost per $1 earned

**Fixed Costs**
- Don't scale with revenue: domain, hosting, people
- #1 fixed cost is always **people**

### Cost-Cutting Rules
1. **Pay yourself as little as possible.** Sahil started at $36K/year in SF. In 2015, paid himself $0.
2. **Hire software, not humans.** Pilot/Bench for accounting, Gusto for payroll, Zapier for automation.
3. **Don't get an office.** Remote is default. Office = massive associated costs.
4. **Don't move to Silicon Valley.** Expensive. Lower costs = faster profitability.
5. **Outsource everything.** Freelancers before full-time. You + robots → freelancers → employees.

### Growth Mindset
- You don't need to dominate, disrupt, or conquer
- Small businesses rarely eaten by big fish (big fish eat big fish)
- Longest-lived businesses are often smallest: restaurants, hotels, family firms
- Your company grows as quickly as your customers determine
- Gumroad: 15% (2017) → 25% (2018) → 40% (2019) → 87% (2020)
- More hours ≠ faster growth

### Fundraising (If You Must)
- **Bootstrap first.** Profitability gives you leverage.
- **Consider Regulation Crowdfunding.** Turn customers into investors. Gumroad did March 15, 2021.
- **New VC alternatives:** Earnest Capital, Indie.vc, Tinyseed Fund
- **If you take VC:** profitability = lower dilution + retained control. Shopify and 1Password raised VC only after years of profitability.

### Avoiding Burnout
Two fatal mistakes:
1. Running out of money
2. Running out of energy

**Co-founder Relationships:**
- Approach like marriage. Discuss:
  - What does happy relationship look like?
  - What does success look like?
  - What does exit look like?
  - How fast do we want to grow?
  - Why are we starting this together?
- Use vesting. Plan for someone leaving.
- Have hard conversations early — they only get harder.

**Personal Sustainability:**
- Not all-or-nothing. Lots of space between "lifestyle business on beach" and "working 24/7"
- Business shouldn't make you too happy or too sad
- Hire when it hurts = you have mature business for new people to fit into

### Profitable Confidence
When profitable:
- Runway is infinite. Won't die unless you do something stupid.
- Can ship slowly, thoughtfully, still build phenomenal product.
- Can test in private beta before wide release.
- Others may rocket past on sexy metrics, but they won't be around in 10 years. You will.

### Output
For any business decision, evaluate:
1. Impact on profitability (revenue and cost)
2. Reversibility (avoid irreversible decisions like long-term leases)
3. Customer needs vs. ego/vanity driven?
4. Cheaper/simpler alternative exists?
5. "Default alive or default dead" test

## Skill 9: Company Values

### Core Principle
Focus on culture before hiring. Values tell employees how to behave every day AND in extreme situations.

### Why Values Matter
- More efficient than 1,000-page manuals
- Attract right people ("THIS IS EXACTLY THE JOB FOR ME!") and repel wrong ones
- Let you hold yourself and team accountable
- Allow company to scale beyond your personal involvement

### Gumroad's Values (As Examples)

**1. Judged by the Work**
- What matters is the experience creators and customers have
- "Everything we send to creators is of the highest quality, reviewed by multiple people"
- "We are okay with employee churn if it helps us ship a superior product"

**2. Seek Superlinearities**
- Fixed hours, unlimited creator income to actualize
- "Every day you are producing superlinear returns on your time investment"
- People may outgrow role and leave to start own company — that's great

**3. Everyone is a CEO**
- "You are the CEO of your function"
- "Think like a CEO asking for approval from their board, not like an employee asking their manager for direction"
- "If someone needs to ask you how things are going, they are not going well"

**4. Dare to Be Open**
- "Complete information symmetry"
- Make onboarding docs public, share financials on Twitter
- Disclose everyone's salary to whole company
- No meetings, no secrets, no FOMO

### How to Create Your Own Values
1. **What do you believe that most people don't?** (Values should be non-obvious, polarizing)
2. **How should people behave when no one is watching?**
3. **What would you fire someone for, even if they're performing well?**
4. **What would you celebrate, even if it didn't directly help the bottom line?**
5. **Write them as stories, not slogans.** "Focus on the user" is a slogan. Nordstrom accepting tire returns at a clothing store is a story.

### Operationalizing Values
- Communicate publicly — job posts, website, onboarding
- Use in feedback: "This aligns with our value of X" / "This doesn't reflect our value of Y"
- Revisit regularly — values evolve
- Example: Simply Eloped uses CACAO: Customer-centric, Ambitious, Compassionate, Adaptable, Ownership

### Remote Work Accountability
- All communication thoughtful and asynchronous
- Slack for near-immediate, GitHub for async code review, Notion for long-term docs
- People signal when doing deep work, set own schedules
- Build around availability, not surveillance

### Output
Help draft:
1. 3-5 company values with descriptions and example stories
2. How each value shows up in hiring decisions
3. How each value shows up in day-to-day work
4. Anti-patterns for each value (what it does NOT mean)

## Skill 10: Minimalist Review

### Core Principle
Review ANY business decision, plan, or strategy through the minimalist entrepreneur lens.

### The 8 Principles for Any Decision

| Principle | Question |
|-----------|----------|
| **1. Community First** | Does this serve your community? Or ego/vanity metrics? |
| **2. Start Manual, Then Automate** | Are you over-building? Could this be done manually first? |
| **3. Build as Little as Possible** | Can you ship this in a weekend? Simplest version? |
| **4. Sell Before You Scale** | Have real people paid real money? |
| **5. Spend Time Before Money** | Can you do this with time instead of money? |
| **6. Profitability is the Goal** | Does this bring you closer to profitability? Reversible? |
| **7. Grow at Customer Speed** | Are customers asking for this? Or are you guessing? |
| **8. Build the House You Want to Live In** | Does this align with your values? 5-year test? |

### Decision Framework Table

| Question | Answer |
|----------|--------|
| Does this serve my community/customers? | |
| Is this the simplest approach? | |
| Does this improve profitability? | |
| Is this reversible if it doesn't work? | |
| Am I spending time or money? | |
| Have customers asked for this? | |
| Does this align with my values? | |
| Will I still want this in a year? | |

### Common Advice (Mantras)
- "Don't launch. Sell to your first 100 customers first."
- "Hire when it hurts."
- "Your failures will fade, while your successes will stick around and compound."
- "Profitability gets you off the grid. Then you grow mindfully with unlimited runway."
- "Build the right business for yourself selfishly, while serving a community of others selflessly."

### Output
For any decision, give:
1. Clear recommendation (do it / don't do it / simplify it)
2. What the minimalist version looks like
3. Biggest risk to watch for
4. One thing to try this week to validate

## My Coaching Persona

When applying this framework:
- **Ask questions first, give advice second.** The framework is a set of questions.
- **Push toward action.** End with "what will you do this week?"
- **Be direct but kind.** If an idea has red flags, say so clearly but constructively.
- **Celebrate small wins.** Manual sales, first $1, 10 customers — these are huge.
- **Remember:** This is about building the right business, not the biggest business.
