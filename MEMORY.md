## Article Structure Templates (ROTATE — Never use same structure twice in a row)

To avoid template detection by AdSense reviewers, alternate between these 6 structures. Each article MUST use a different structure than the previous article.

### Template A: Narrative Opening (Story-Driven)
**Best for**: Company profiles, founder stories, market disruptions

1. **Hook Scene** — Open with a specific moment, conversation, or observation (1-2 paragraphs, no table)
2. **The Discovery** — What happened? How did we get here? (2-3 sections)
3. **The Numbers** — Data tables appear mid-article, not at top (2-3 tables)
4. **Why It Matters** — Analysis of implications (1 section)
5. **What Comes Next** — Future outlook with milestones (1 section)
6. **Social Voices** — Comments interspersed OR at bottom (6 comments)

**Example opening**: *"It was 2 AM in Shenzhen when the alert hit. Cambricon's CFO stared at the screen, watching Q1 revenue cross ¥28 billion — 159% growth. The number he'd been waiting five years to see."*

### Template B: Contrarian Take (Argument-Driven)
**Best for**: Market analysis, trend predictions, competitive analysis

1. **Provocative Thesis** — State a counter-intuitive claim upfront (1 paragraph)
2. **The Conventional Wisdom** — What everyone believes (1 section)
3. **The Evidence** — Data that contradicts conventional wisdom (3-4 tables)
4. **The Real Story** — What's actually happening (2 sections)
5. **Implications** — Who wins, who loses (1 section)
6. **Social Voices** — Mixed reactions to the thesis (6 comments)

**Example opening**: *"Everyone thinks China's AI chip industry is surviving despite US sanctions. The Q1 numbers prove the opposite: it's thriving because of them."*

### Template C: Deep Dive Single Subject (Profile)
**Best for**: Single company, single product, single technology

1. **The Subject** — Introduce ONE company/product with a compelling stat (1 section)
2. **Origin Story** — How it started, key decisions (1-2 sections)
3. **Product/Technology Deep Dive** — Technical details, benchmarks (2-3 tables)
4. **Business Model** — How it makes money, unit economics (1 section, 1 table)
5. **Competitive Position** — vs rivals (1 section, 1 table)
6. **Future & Risks** — What's next, what could go wrong (1 section)
7. **Social Voices** — User/insider reactions (6 comments)

### Template D: Comparative Framework (Side-by-Side)
**Best for**: Two companies, China vs US, before/after analysis

1. **The Comparison Setup** — Two subjects, one question (1 paragraph)
2. **Subject A Deep Dive** — Full analysis (2 sections, 2 tables)
3. **Subject B Deep Dive** — Full analysis (2 sections, 2 tables)
4. **Head-to-Head** — Direct comparison table (1 section, 1 large table)
5. **Synthesis** — What the comparison reveals (1 section)
6. **Social Voices** — Debate format comments (6 comments, mixed A vs B)

### Template E: Timeline / Historical Arc
**Best for**: Industry evolution, policy impact, technology progression

1. **The Present Moment** — Current state as anchor (1 section, 1 table)
2. **Phase 1: Origins** — How it started (1 section)
3. **Phase 2: Inflection** — Key turning point (1 section, 1 table)
4. **Phase 3: Acceleration** — Recent explosion (1-2 sections, 2 tables)
5. **Phase 4: What's Next** — Future milestones (1 section)
6. **Social Voices** — Comments from different time periods (6 comments)

### Template F: Phenomenon Analysis (Societal Impact)
**Best for**: User behavior trends, cultural impact, mass adoption stories

1. **The Phenomenon** — Describe a visible social/behavioral change (1-2 paragraphs)
2. **The Scale** — Numbers showing how big it is (1 section, 1 table)
3. **User Stories** — 2-3 specific user cases/examples (2 sections)
4. **Behind the Scenes** — Technology/business enabling it (1-2 sections, 2 tables)
5. **Global Parallels** — How this compares to other markets (1 section)
6. **Social Voices** — Real user comments (6 comments)

## Content Template Breaking Rules

### ❌ NEVER do this (template fingerprints):
- [ ] Every article starts with "Executive Summary" heading
- [ ] Every article has exactly 8-9 sections
- [ ] Every article puts a data table in the first 300 words
- [ ] Every article ends with the same "Social Media Comments" section format
- [ ] Every article uses "Chapter X" labeling
- [ ] Every article has exactly 6 social comments

### ✅ ALWAYS vary these:
- [ ] Opening style: story / provocative thesis / single stat / user quote
- [ ] Section count: 6-10 sections (vary per article)
- [ ] Table count: 4-8 tables (vary per article)
- [ ] Table placement: some early, some mid, some late
- [ ] Social comment placement: bottom-only vs interspersed vs sidebars
- [ ] Section labels: "Chapter X" vs "Part X" vs no label vs descriptive heading
- [ ] Comment count: 5-7 comments (don't always use exactly 6)
- [ ] Comment sources: rotate which platforms appear (don't always use all 6)

## Quality Standards Checklist (BEFORE PUBLISHING)

### Length & Depth
- [ ] **Word count: 2,800 - 3,500 words**
- [ ] **8-9 sections minimum** (H2 headings)
- [ ] **Reading time: 14-18 minutes**

### Data & Analysis
- [ ] **6-8 structured tables** with proper headers
- [ ] **Original analysis** (not just news summary)
- [ ] **Comparative metrics** (vs competitors)

### Visual Content
- [ ] **Hero image** (1200x600, Unsplash AI/tech themed) — **每篇用不同图片**
- [ ] **2-3 inline images** (800x400) — **不重复**
- [ ] **All images have captions**

### Social Media Comments
- [ ] **6 comments total**, mixed sources (Zhihu, Xiaohongshu, Weibo, Twitter/X, Douban, GitHub)
- [ ] **Bilingual format**: Chinese quote + English translation
- [ ] **Diverse viewpoints**: Positive, skeptical, analytical

### SEO Optimization
- [ ] **Meta title**: < 60 chars
- [ ] **Meta description**: 150-160 chars
- [ ] **Keywords**: 8-10 relevant terms
- [ ] **URL slug**: kebab-case, keyword-rich
- [ ] **Related articles**: 4 internal links

## Publishing Workflow (Summary)

1. Write article → `content/posts/[slug].md`
2. Update `lib/posts-meta.js` → add to `allPosts` array
3. Update `app/blog/[slug]/page.js` → add `postMetadata` entry
4. `npm run build` (auto-runs `check-images` + `sitemap`)
5. **Verify**: `dist/blog/` count == markdown count
6. `git add -A && git commit && git push`
7. **Verify online**: `curl https://www.ainchina.com/blog/[slug]/`
